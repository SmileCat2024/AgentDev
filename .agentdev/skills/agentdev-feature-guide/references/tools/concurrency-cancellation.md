## 执行分组

一个 assistant turn 中的工具调用按以下顺序处理：

1. 检查是否违反独占批次；
2. 并发执行所有 `parallelizable: true` 工具；
3. 按顺序执行其余工具；
4. 按原始 tool call 顺序写回结果。

并发工具总是在串行工具之前完成。不要让串行工具依赖同批次并发工具的输出；模型在生成这一批调用时也看不到前一个工具结果。

## 并发判定

只有能证明互不影响时才标记并发：

```ts
parallelizable: true
```

安全候选：

- 不同 ID 的只读查询；
- 不同文件的纯读取；
- 无共享缓存写入的计算；
- 作用于独立资源并具备幂等性的操作。

保持串行：

- 修改同一 Feature 状态；
- 写同一文件或目录；
- 更新同一远端对象；
- 依赖顺序、锁或事务；
- 会改变后续工具配置或权限。

## 共享状态

即使工具业务是只读，缓存、统计和 lazy initialization 也可能产生写入。采用一种策略：

- 在初始化阶段完成资源创建；
- 用并发安全的缓存；
- 对共享写入加互斥；
- 将统计改为原子或允许近似；
- 去掉 `parallelizable`。

不要在多个并发工具中修改同一个普通数组、`Map` 或文件。

## 中断

框架将 `AbortSignal` 放入工具 context，并让等待过程与 signal 竞争：

```ts
execute: async (args, context) => {
  return fetch(url, { signal: context?.signal });
}
```

框架停止等待不等于底层操作停止。底层库忽略 signal 时，操作仍可能在后台完成。

长循环主动检查：

```ts
for (const item of items) {
  if (context?.signal?.aborted) {
    throw new DOMException('Aborted', 'AbortError');
  }
  await processItem(item, context?.signal);
}
```

子进程、流和事件监听器要在 abort 时终止并解绑监听器。

## 超时与重试

外部调用设置明确超时，并与 call signal 组合。超时错误与用户中断分开表达。

只自动重试：

- 明确的瞬时网络失败；
- 服务器限流且提供退避信息；
- 幂等读操作；
- 带幂等键的安全写操作。

不要自动重试未知写入结果。连接断开可能发生在服务器已提交之后。

## 幂等

为副作用操作定义稳定请求键：

```text
featureName + toolCallId + logicalOperationId
```

并保存外部返回 ID。重试时先查询已有结果，再决定继续。创建、发送、发布、付款和启动任务尤其需要明确幂等策略。

rollback 只恢复 Agent 与 Feature 逻辑状态，不撤销外部副作用。写工具不要把逻辑回滚当成远端事务回滚。

## 验证

- 两个并发工具确实重叠执行；
- 结果仍按原始调用顺序写入；
- 并发失败不丢失其他结果；
- abort 到达底层操作；
- 中断后没有遗留监听器、进程或写入；
- 超时与用户中断返回不同错误；
- 重试不会重复创建外部对象；
- 独占工具与其他工具同批时全部不执行。
